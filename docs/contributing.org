* Engineering standard

Changes follow [[file:../ENGINEERING.md][=ENGINEERING.md=]].  Keep physical
units, coordinate conventions, numerical tolerances, boundary names, and
operation ordering explicit in code and tests.

* Before editing

Read the implementation, its tests, and the relevant public document.  Identify
the owner of the changed data or policy and make the smallest coherent change
at that boundary.

Do not weaken a validation tolerance to turn an unexplained result into a pass.
Record format-specific or solver-specific failure separately from the upstream
geometry or mesh when their checks remain valid.

* Tests

Run the focused test first, then the appropriate suite:

#+begin_src sh
uv run pytest
uv run pytest -m integration
uv run ruff check bearing_cfd studies tests
uv run python -m compileall -q bearing_cfd studies tests
#+end_src

Integration tests invoke CAD or mesh kernels or probe external runtimes.
Capability-dependent tests must skip when the external tool or licence is not
available; they must not infer a live pass from a parser fixture.

* Documentation

Use the Diátaxis category that matches the reader's task:

- tutorials lead a new user through one complete result;
- how-to guides provide steps for a specific task;
- reference pages state exact inputs, outputs, schemas, and statuses;
- explanations describe physical models, algorithms, architecture, and
  trade-offs.

Study reports contain current inputs, results, and limitations.  Use Git when
historical context is needed.

Use relative Org =file:= links and link source functions or tests when a claim
depends on a specific implementation.  Generated =out/= paths may appear in
command examples but are not valid GitHub evidence links.  Link selected
versioned results under =evidence/= instead.

* Numerical claims

State the scope of each result:

| Claim | Required evidence |
|---+---|
| geometry | formula, construction, and geometric validation |
| mesh topology | face/cell census and connected-region checks |
| mesh quality | named metric, implementation, threshold, and mesh resolution |
| interchange | source-array comparison after reading the exported file |
| live solver import | actual runtime transcript and count/scale audit |
| numerical convergence | declared residual, conservation, and field-change checks |
| physical validation | comparison with an independent numerical or experimental target |

Do not transfer a pass between rows.  A valid mesh does not establish a valid
flow model, and a converged flow field does not establish agreement with an
experiment.

* Commits

Keep one logical change per commit.  Include the source, tests, documentation,
and compact fixtures needed for that change.  Generated meshes, solver time
directories, processor partitions, logs, and caches remain outside Git.
