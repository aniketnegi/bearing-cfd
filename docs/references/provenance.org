* Data lineage

#+begin_example
GeometryInputs (mm)
  -> geometry/model.py: resolved dimensions and analytic invariants
  -> geometry/cad.py: native BREP, optional STEP, params.json
       -> meshing/brep_preflight.py: OCC import and SI copy
       -> meshing/surface_smoke.py: boundary-only Tri3 check
       -> meshing/no_port.py: no-feed Hex8 reference
       -> meshing/surface_inlet.py: mesh-aligned bore inlet
       -> meshing/body_fitted_inlet.py: conforming circular bore inlet
       -> meshing/central_feed.py: film-and-passage Prism6 mesh
            -> mesh_arrays.npz + manifest.json + mesh_report.json
                 -> conical_journal/interchange.py
                      -> clean MSH, CGNS, and Fluent-ASCII files

simulation/reynolds_jfo.py
  -> pressure, fill, flow, force, torque, and convergence records

openfoam/solvers/jfoBearingFoam
  -> independent native implementation using tracked case dictionaries
#+end_example

CAD coordinates and inputs use millimetres.  Canonical solver-mesh coordinates
use metres.  The conversion factor is applied at the meshing boundary and
recorded in stage reports.

* Generated artifacts

Installed commands write below =out/conical_journal/=.  Each published
generation contains =run.json= with:

- the invoked argument array and resolved inputs with units;
- producing Git commit, dirty-state flag, and source-file hashes;
- upstream artifact paths and SHA-256 hashes;
- relevant tool versions;
- output paths, roles, and hashes;
- acceptance state and the replaced artifact identity, when present.

The =run.json= schema is listed in
[[file:../operations/outputs-and-reports.org][Outputs and reports]].  Stage-specific
reports remain authoritative for geometry, topology, quality, format, and
solver checks.

Output directories are published atomically.  A failed generation cannot
leave new files beside an accepted report.  Failure-only directories do
not contain solver-eligible meshes or exchange files.

* Versioned evidence

Selected figures, animations, and compact result tables live in
[[file:../../evidence/conical_journal/][=evidence/conical_journal/=]].  They are
presentation artifacts, not pipeline inputs.

[[file:../../evidence/conical_journal/manifest.json][=evidence/conical_journal/manifest.json=]]
binds each collection to a SHA-256 tree hash and a study manifest.  A tree hash
includes every relative path and file hash in sorted order.  The corresponding
=studies/conical_journal/*/study.json= records the scientific question, status,
source commit, commands, external tools, source artifacts, and expected
outputs.

Large meshes, mapped initial fields, solver time directories, processor
partitions, and raw logs stay under =out/=.  A study that depends on them lists
their hashes and regeneration procedure in its =study.json=.

* Claim boundaries

| Evidence | What it establishes | What it does not establish |
|---+---+---|
| analytic geometry checks | resolved dimensions and clearance laws | valid CAD topology |
| native BREP validation and round trip | accepted OCCT geometry | accepted STEP exchange |
| surface smoke mesh | boundary classification and surface meshing | three-dimensional solver readiness |
| volume-mesh topology and quality | connectivity, geometry, named boundaries, and stated metric gates | valid flow physics |
| static format round trip | serialized coordinates, cells, and group membership | successful licensed solver import |
| =FLUENT_IMPORT_PASS= | live Fluent import, check, count/scale audit, and native save | converged or validated CFD |
| numerical convergence gate | satisfaction of the declared numerical checks | agreement with physical measurements |
| experimental or independent comparison | only the quantities and conditions compared | transfer to undisclosed operating conditions |

Pass states do not transfer between rows.  In particular,
=STATIC_PASS_FLUENT_NOT_RUN= and =FLUENT_IMPORT_PASS= are distinct statuses,
and convergence is not physical validation.
